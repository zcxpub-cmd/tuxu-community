# v0.4.0 生图回填修复

本次在现有 v0.4.0 下追加修复，不新增版本号。首次发布的标签快照保持可追溯，修复源码位于最新 `main` 和原发布页的 `Tuxu_v0.4.0_source.zip`，后者对应的提交与校验值写在发布说明中。GitHub 自带的 “Source code” 是首次标签快照，请使用具名修复包或最新 `main`。

## 问题与变化

Codex 原生图片工具可能返回与名义请求不同的常见画幅。旧导入逻辑一律要求比例相差不超过 5%，即使图片和完成回执已在本机，也会拒收；错误随后被归入“执行状态待核查”，导致页面持续等待。

- 原生模式按批准的横向或纵向方向接收列明的常见比例，完整保留原始像素，并在选图区提示实际尺寸与请求的差异。方形、方向、像素上限和可读性继续校验。通用 runner 仍保持严格比例校验；具体范围见[本机智能体文档](local-agent.md)。
- 只有身份、授权和冻结提示词均验证通过的完成回执，且图片错误属于明确的三项校验错误，才记录为确定失败。其他未知错误仍保留待核查，不自动重发。
- 最终保存与作业结束均在事务中复核当前状态。已失败请求不会被晚到的成功覆盖；已保存图片重复回填保持幂等；旧作业不能覆盖后续活跃任务。
- 重启可以导入同一请求目录中已有的有效完成回执，不会重新调用图片工具。取消状态保持不变，已返回的有效图片继续保留供用户选用。

## 更新与验证

停止正在运行的图序，备份 Community 数据目录，用修复源码替换程序并重新运行 `./setup.sh`、`./start.sh`。保留原来的数据目录和本机智能体配置，不要把私有配置复制到源码包。已提交请求只读取原回执，不需要点击重试。

本轮本地后端 690 项测试、前端构建及 11 组检查通过；其中独立复核 64 项包含原生画幅、回执错误与并发终态反例。另从真实已有回执恢复两张图片，逐像素核验与原图相同，原授权、请求标识和尝试次数保持不变，浏览器确认两图均已载入。本轮没有新增生图调用。该验证证明回填修复，不代表所有模型或画面内容质量都已验收。
