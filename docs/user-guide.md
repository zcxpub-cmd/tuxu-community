# 使用说明与局限

## 1. 导入文章

支持 DOCX、Markdown、TXT 与直接粘贴。当前界面粘贴上限为 10,000 字符，导入文件上限为 10 MB。先用短文验证自己的模型与文档流程，再处理较长内容。

选择论文/科普、新闻/传播、小说或报告类型，保存原稿副本。界面的示例是自制演示内容，不是实验数据或新闻证据。

## 2. 检查建议图位

由本地模型分析后，逐项核对对应段落、配图理由、画面描述、比例和图注。建议可能不完整或与原意不符，可以修改、删除或补充。保存修改会使旧生成授权和选图失效，旧图保留为历史记录。

无需配图时删除图位并保存零图方案，可保留正文导出；不需要为零图方案授权生图。

## 3. 简单画面导演台

选择风格和明暗，把物体拖到希望出现的大致位置；也可用九宫格位置快捷操作。物体描述应简短清楚，明确数量、外观与身份。需要时填写纯环境背景，减少主体与背景混淆。

相机、光线、精确几何与景深等选项默认折叠。统一应用视觉设置会保留各图自己的物体与位置。保存画面后进入授权。

方框与比例是生成指导，不是排版软件或三维引擎的几何锁定。模型可能忽略明暗、位置或对象关系；更多对象和复杂遮挡尤其需要人工检查。

## 4. 授权与生成

选择当前可用的生图路线，检查画面简述、物体位置、模型与尝试上限，确认后提交。云端会收到当前画面描述与构图；文章分析仍使用配置的 Ollama。具体模型准备见[模型配置](models.md)。

配置完整、模型可见与实际生图成功分别展示。最近验证记录只描述当时的结果，不保证权限持续有效。更改模型、密钥、服务或方案后，需要按页面要求重新确认。

超时或连接中断可能留下未决请求。恢复原任务，不要通过新授权、换供应商或重新抽图假设原请求已失败。Codex 路线必须有支持的宿主会话继续处理，等待队列本身不是成功图片。

## 5. 选图与处理

检查主体数量、物体外形、位置、文字、事实及示意标注。确认合适后选用；旧方案的图片不能插入当前版本。

处理功能是轻度中值降噪和 Lanczos 传统插值放大，保留原图。它不是 AI 超分，也不会纠正主体缺失、畸形、伪字或科学错误。

生成图片不自动代表可商用、可署名为实拍或无第三方权利问题；使用者应核对所用模型、参考素材和交付场景。

## 6. 插入与导出

在原文预览中检查位置和连续编号，确认插入到原稿副本，导出 DOCX、Markdown 图片包或 HTML。实际分页与网页预览可能不同，需在 Word/WPS 等文档软件中检查正文顺序、图片、图注及分页。

DOCX 重建不承诺保留复杂公式、浮动对象、修订、脚注、页眉页脚及所有样式。请保留原文件；复杂稿件可以先用简化文本走通配图，再由作者或编辑排版。

## 科研与新闻

模型生成的科学图示应由相关作者核对结构、比例、数据与文字；社区版不是专业科研制图验证系统。论文、报告与新闻中的生成画面应明确标识为示意，不能充当真实实验结果或现场证据。

## 模板与数据

通用基础模板随源码公开。前端仅显示简述，不展示完整生成文本；本机管理者可查看源码与自己数据，这不是模板保密机制。高级私有模板不在社区仓库中，也不是必需依赖。

稿件、任务、密钥和媒体保存在用户数据目录；详情见[安全说明](security.md)。
